# SQL:2016 及主流 SQL 规范要点

## 1. 基本语法规范

- 关键字大写，表名、字段名小写或驼峰。
- 每条语句以分号结尾。
- 缩进清晰，便于阅读维护。

## 2. 数据定义（DDL）

- 推荐使用 `CREATE TABLE IF NOT EXISTS`、`DROP TABLE IF EXISTS`。
- 字段类型明确（如 `INT`、`VARCHAR(255)`、`DATE`）。
- 主键、唯一约束、外键、默认值、非空等约束要声明清楚。
- 建议使用自增主键（如 `AUTO_INCREMENT` 或 `SERIAL`）。

## 3. 数据操作（DML）

- `INSERT INTO ... VALUES ...`，推荐显式列名。
- `UPDATE ... SET ... WHERE ...`，必须加 WHERE 条件，防止全表更新。
- `DELETE FROM ... WHERE ...`，同样必须加 WHERE 条件。

## 4. 查询（SELECT）

- 推荐显式列名，不用 `SELECT *`。
- 多表关联用 `JOIN`，并加上表别名。
- 复杂查询建议分多行书写，便于维护。
- 支持窗口函数（如 `ROW_NUMBER()`、`RANK()`、`OVER()`）。
- 支持 `WITH` 语句（公用表表达式，CTE）。

## 5. 事务与并发

- 明确使用 `BEGIN`/`COMMIT`/`ROLLBACK` 控制事务。
- 推荐使用合适的隔离级别（如 `READ COMMITTED`、`REPEATABLE READ`）。

## 6. 规范命名

- 表名、字段名见名知意，统一风格（如下划线、驼峰）。
- 避免使用 SQL 保留字作为标识符。

## 7. 安全与性能

- 所有输入参数必须防 SQL 注入（如用预编译语句）。
- 合理建索引，避免全表扫描。
- 大批量操作建议分批提交。

## 8. 兼容性与扩展

- 遵循 SQL 标准，避免使用特定数据库的专有语法（如非必要）。
- 充分利用标准函数和表达式。

---

### SQL:2016 新特性

- JSON 数据类型与操作（如 `JSON_TABLE`、`IS JSON`）。
- 更丰富的窗口函数。
- 更强的分区表支持。
- 标准化的 MERGE 语句（合并插入/更新）。
